Objetivo del Final Boss

Este laboratorio final simula un escenario de encadenamiento real: reconocimiento, acceso inicial, movimiento lateral y escalada a root para recuperar la flag final.

Cadena de explotación sugerida

  1. Reconocimiento del stack y servicios internos expuestos.
  2. Identificación de un vector inicial (inyección, SSRF o credenciales reutilizadas).
  3. Ejecución remota limitada y estabilización de shell.
  4. Escalada de privilegios mediante mala configuración local.
  5. Acceso al contexto root y extracción de la flag final.

Flujo práctico (ejemplo)

# 1) Enumeración base
id
uname -a
sudo -l
find / -perm -4000 -type f 2>/dev/null

# 2) Estabilizar TTY
python3 -c 'import pty; pty.spawn("/bin/bash")'
export TERM=xterm

# 3) Buscar credenciales y rutas sensibles
grep -R "password\|token\|secret" /home /opt /etc 2>/dev/null | head

# 4) PrivEsc (según vector detectado)
# Ejemplo típico: binario SUID vulnerable o sudo mal configurado

# 5) Flag final
cat /root/final_boss/final_flag.txt

Mitigaciones

  • Principio de mínimo privilegio para servicios y usuarios.
  • Eliminar SUID innecesarios y revisar reglas de sudo.
  • Rotación de credenciales y segregación de secretos.
  • Hardening de contenedores/hosts y monitoreo de comandos anómalos.
